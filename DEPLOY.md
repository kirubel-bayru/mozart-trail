# Deploy Mozart's Trail (Neon + Render + Cloudflare Pages)

This guide deploys the app in three free tiers:

| Service | Role |
|---------|------|
| [Neon](https://neon.tech) | PostgreSQL database |
| [Render](https://render.com) | Express API (`backend/`) |
| [Cloudflare Pages](https://pages.cloudflare.com) | React frontend (`frontend/`) |

**Prerequisite:** Push this repo to GitHub (both Render and Cloudflare deploy from Git).

---

## Step 0 — Push to GitHub

If the project is not on GitHub yet:

```bash
git add .
git commit -m "Prepare production deployment"
git remote add origin https://github.com/YOUR_USER/mozart.git
git push -u origin main
```

---

## Step 1 — Neon (database)

1. Sign up at [neon.tech](https://neon.tech) and create a project (e.g. `mozart-trail`).
2. On the project dashboard, open **Connection details** and copy the **pooled** connection string.  
   It looks like:
   ```
   postgresql://user:password@ep-xxx.region.aws.neon.tech/neondb?sslmode=require
   ```
3. Save this as `DATABASE_URL` — you will paste it into Render in Step 2.

Tables are created automatically when the backend starts (`server.ts` runs migrations).

**Optional:** In the Neon SQL editor, verify after deploy:

```sql
SELECT tablename FROM pg_tables WHERE schemaname = 'public';
```

---

## Step 2 — Render (backend API)

1. Sign up at [render.com](https://render.com) with GitHub.
2. Click **New → Blueprint** and connect your `mozart` repo.  
   Render reads `render.yaml` at the repo root and creates a **Web Service** named `mozart-api`.
3. When prompted for environment variables, set:

   | Variable | Value |
   |----------|-------|
   | `DATABASE_URL` | Neon connection string from Step 1 |
   | `CORS_ORIGIN` | Leave blank for now — update after Step 3 |

   `JWT_SECRET` is auto-generated by the blueprint.

4. Deploy and wait for **Live**. Copy your API URL, e.g.:
   ```
   https://mozart-api.onrender.com
   ```

5. Verify the API:

   ```bash
   curl https://mozart-api.onrender.com/api/health
   curl https://mozart-api.onrender.com/api/db
   ```

   `/api/db` should return `"database": "connected"`.

**Free tier note:** Render sleeps after ~15 minutes idle. The first request after sleep may take 30–60 seconds.

### Manual Render setup (without Blueprint)

If you prefer not to use `render.yaml`:

- **Root Directory:** `backend`
- **Build Command:** `npm install && npm run build`
- **Start Command:** `npm start`
- **Health Check Path:** `/api/health`
- **Environment:** `NODE_ENV=production`, plus `DATABASE_URL`, `JWT_SECRET`, `CORS_ORIGIN`

Generate a JWT secret locally:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

## Step 3 — Cloudflare Pages (frontend)

1. Sign up at [dash.cloudflare.com](https://dash.cloudflare.com) → **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. Select your `mozart` repo.
3. Build settings:

   | Setting | Value |
   |---------|-------|
   | **Production branch** | `main` |
   | **Framework preset** | None |
   | **Build command** | `cd frontend && npm install && npm run build` |
   | **Build output directory** | `frontend/dist` |

4. **Environment variables** (Settings → Environment variables → Production):

   | Variable | Value |
   |----------|-------|
   | `NODE_ENV` | `production` |
   | `API_BASE_URL` | `https://mozart-api.onrender.com` (your Render URL, no trailing slash) |
   | `ORS_API_KEY` | Your OpenRouteService key (optional, for walking directions) |

5. Deploy. Your site will be at something like:
   ```
   https://mozart-trail.pages.dev
   ```

6. **Update Render CORS** — in Render → `mozart-api` → Environment:

   ```
   CORS_ORIGIN=https://mozart-trail.pages.dev
   ```

   For preview branches too, use comma-separated origins:

   ```
   CORS_ORIGIN=https://mozart-trail.pages.dev,https://abc123.mozart-trail.pages.dev
   ```

   Save and redeploy the Render service.

7. Hard-refresh the Cloudflare site and test:
   - Home page loads
   - **Log in to Explore** → register / log in
   - After login → hunt map works
   - Quiz progress persists (check Neon tables)

## Environment variable reference

### Backend (Render)

| Variable | Required | Description |
|----------|----------|-------------|
| `DATABASE_URL` | Yes | Neon PostgreSQL connection string |
| `JWT_SECRET` | Yes | Random secret for auth tokens |
| `CORS_ORIGIN` | Yes | Cloudflare Pages URL (comma-separated for previews) |
| `PORT` | No | Set by Render automatically |
| `NODE_ENV` | Yes | `production` |
| `MUSIC_API_URL` | No | External music API if configured |

### Frontend (Cloudflare Pages)

| Variable | Required | Description |
|----------|----------|-------------|
| `API_BASE_URL` | Yes | Render API URL (baked in at build time) |
| `ORS_API_KEY` | No | OpenRouteService key for directions |
| `USE_MUSIC_API` | No | `true` if using backend music proxy |

**Important:** Changing `API_BASE_URL` on Cloudflare requires a **new deployment** (rebuild), because Rspack embeds it at build time.

## Custom domain (optional)

- **Cloudflare Pages:** Pages → your project → **Custom domains**
- **Render:** Service → **Settings → Custom Domains** (update `CORS_ORIGIN` and rebuild frontend with new `API_BASE_URL` if API domain changes)

---

## Troubleshooting

| Problem | Fix |
|---------|-----|
| Login fails / CORS error | `CORS_ORIGIN` on Render must exactly match the browser URL (including `https://`, no trailing slash) |
| `database: disconnected` | Check `DATABASE_URL` on Render; use Neon **pooled** connection string |
| API slow on first load | Render free tier cold start — normal |
| Routes 404 on refresh | `_redirects` in `frontend/public/` should copy to `dist/` — redeploy frontend |
| Walking directions missing | Set `ORS_API_KEY` in Cloudflare and redeploy |

```bash
npm run dev
```

Use local Postgres or point `DATABASE_URL` at Neon for shared dev data.
